## 4. Pengukuran di browser

Metode: Chromium headless, berkas lokal `qa-sticky/ukur.html` (di scratch, bukan di repo) berisi **markup kelas persis**
`DataTable.jsx` + 9 kolom persis `Orders/Index.jsx`, 21 baris, dan **CSS hasil `npm run build`** (disalin ke scratch).
Wadah gulir = `min(1200, viewport − sidebar 240) − padding utama − 2 px border` (mengikuti `AdminLayout.jsx:173,229`
dan token `w-sidebar 240px`). Ini replika, **bukan** halaman `/admin/pesanan` asli (butuh login).

### 4.1 Hasil per lebar

| Viewport | Wadah | Tabel | Overflow | Sel Aksi (px) | Tumpang tindih | Detail terlihat | Hit test di tombol |
|---|---|---|---|---|---|---|---|
| 1600 | 1148 | 1133 | 0 | 1070–1142 | 0 px | ya | `A|Detail` |
| 1440 | 1148 | 1133 | 0 | 1070–1142 | 0 px | ya | `A|Detail` |
| 1280 | 988 | 1072 | 99 | 914–982 | 68 px (kolom "Status pesanan") | ya | `A|Detail` |
| 1024 | 732 | 1059 | 342 | 658–726 | 0 px ke kolom 8 (kolom 8 di luar pandangan) | ya | `A|Detail` |
| 768 | 732 | 1045 | 328 | 659–726 | 0 px ke kolom 8 | ya | `A|Detail` |
| 360 | 324 | 1024 | 715 | 252–318 | 0 px ke kolom 8 | ya | `A|Detail` |

- `kolom: 9` dan daftar judul lengkap (Kode pesanan … Aksi) pada semua lebar → DoD #1.
- `position: sticky`, latar `rgb(255, 255, 255)`, border kiri `1px rgb(229, 231, 235)` pada sel Aksi (1280).
- `scrollLeft = max` → sel Aksi **tidak bergeser** (tetap 914–982 di 1280); kolom lain yang bergerak → perilaku lengket benar.
- `scrollTop = 200` (21 baris, isi 1221 px > wadah 615 px) → baris 1 terpotong (`top = −146`), header tetap di `9–53`;
  `elementFromPoint` di pita header mengembalikan `TH` (z=20 untuk Aksi, z=10 untuk kolom lain) → header **tidak** tertimpa sel badan lengket.

### 4.2 Catatan DoD #2 — tumpang tindih 68 px saat tabel lebih lebar dari wadah

Pada 1280 px (kasus paling umum untuk laptop) tabel 1072 px di wadah 988 px. Sel Aksi lengket duduk di
`914–982`, sedangkan kolom "Status pesanan" menempati `843–1013`. Jadi saat `scrollLeft = 0` sel Aksi
menutupi **68 px** (selebar sel Aksi sendiri) dari sisi kanan kolom "Status pesanan" — bagian akhir badge status.
Data tidak hilang: menggulir 99 px ke kanan memunculkan seluruh kolom, dan posisi Aksi tetap menempel.
Pada 1600/1440 (tanpa overflow) tumpang tindih **0 px**.

Sifat ini melekat pada `position: sticky; right: 0` dan sudah diputuskan techlead
(`docs/bugs/t_3f1b4473-detail-tersembunyi.md` §3): Detail selalu terlihat ditukar dengan sedikit tumpang tindih.
Karena bukan cacat kode dan tidak bisa dihilangkan tanpa keputusan produk (mis. menyembunyikan kolom prioritas
rendah di < 1280, atau mengecilkan tipografi tabel), QA **tidak** membuat kartu perbaikan.
Rekomendasi: techlead memilih (a) terima + sesuaikan kalimat DoD menjadi "tidak menutupi kolom lain secara permanen
(data tetap terjangkau dengan scroll)", atau (b) minta varian desain tanpa tumpang tindih.

## 6. Belum diuji (butuh browser/akses)

1. `/admin/pesanan` **asli** sebagai admin (login) — belum diuji, butuh browser + akun admin. Semua angka §4 dari replika
   markup ber-CSS build, bukan tangkapan layar sesi admin.
2. Hover/focus visual sel lengket: aturan CSS ada (§3), tetapi simulasi pointer di sesi ini gagal
   (`Input.dispatchMouseEvent` timeout) → belum diuji, butuh browser.
3. Keyboard Tab ke tombol "Detail" dan fokus terlihat: `Button` varian link tidak punya kelas `focus-visible`
   eksplisit (`resources/js/Components/Button.jsx:12`), jadi bergantung outline bawaan browser → belum diuji, butuh browser.
4. Zoom 200%, Firefox/Safari (sticky pada `border-collapse: collapse`) → belum diuji, butuh browser lain.
5. Regresi visual tabel admin lain (Produk/Stok/Ulasan) → belum diuji, butuh login admin.
