## 2. Ukur lebar tabel vs wadah (viewport 1280 px)

Metode sama dengan laporan bug: markup dengan kelas persis dari `DataTable.jsx` + isi sel
persis dari `Index.jsx` disuntik ke halaman publik `http://127.0.0.1:8000` (CSS aplikasi
hasil `npm run build`), viewport 1280×900. Wadah = 1280 − sidebar `w-sidebar` 240 − padding
utama 48 − border kartu 2 = **990 px**.

| | sebelum (tanpa `sticky`) | sesudah (`sticky: true`) |
|---|---|---|
| lebar wadah | 990 px | 990 px |
| lebar tabel | 1163 px | 1164 px (+1 px border kiri sel lengket) |
| overflow horizontal | 173 px | 174 px (scroll tetap jalan) |
| posisi sel Aksi (rel. wadah) | 1092 → 1163 px | 918 → 990 px |
| tombol Detail terlihat tanpa scroll | **tidak** (tepi kanan 1163 > 990) | **ya** (tepi kanan pas 990) |
| `position` sel Aksi | `static` | `sticky` (`right: 0px`, `z-index: 10`) |
| latar sel Aksi | transparan | `rgb(255, 255, 255)` |
| border kiri | – | `1px rgb(229, 231, 235)` (`border-line`) |

Uji gulir pada tabel yang sama:

- `scrollLeft = 0` → sel Aksi 918 → 990 (menempel kanan).
- `scrollLeft = 174` (paling kanan) → sel Aksi tetap 918 → 990 (tidak ikut bergeser, kolom
  lain yang bergerak).
- 21 baris + `scrollTop = 200` → header Aksi tetap di `top: 0` wadah dan `elementFromPoint`
  di atas header mengembalikan `TH.sticky.top-0.h-tableHead` (header tidak tertimpa sel
  lengket badan); `z-index` header 20 vs sel badan 10.
- Vertical scrollbar (lebar 15 px) membuat sel menempel ke tepi padding box (975), bukan
  tepi border box — perilaku normal `overflow-auto`, tombol tetap terlihat penuh.
